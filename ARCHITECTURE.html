DawChecker Security — Architecture Map

AI-agent security review and policy decision layer · Local-first

Purpose & trust rule

Reviews proposed actions from AI agents: shell, file access, package installation, MCP calls, and DAW/plugin surfaces. Returns ALLOW, BLOCK, or ASK and can record a local receipt. DawChecker is not a sandbox and cannot guarantee enforcement if its host ignores the result.

LLM is an untrusted proposer, not an authorization authority. The trusted runtime must enforce policy before every side effect. Fail closed if enforcement cannot obtain a valid decision.

Decision flow

LLM / Agent proposes
→
Host builds ActionContext
→
Classifiers assign labels/risk
→
Current policy
→
Approval memory
→
Result + optional receipt
→
Host enforcement gate

On the security branch, remembered approvals are consulted only after current classifiers and policy; current policy BLOCK wins. Approval fingerprints include agent/session/cwd context.

Components

  • src/dawchecker_security/core.py — ActionContext, fingerprints, classifier orchestration, policy evaluation, remembered decision handling, result, receipt hook.
  • src/dawchecker_security/policy/engine.py — local YAML/JSON policy; ordered first-match rules.
  • src/dawchecker_security/approvals/memory.py — local remembered decisions with HMAC tag; filesystem hardening still needed.
  • src/dawchecker_security/receipts/store.py — local append-only JSONL receipts; concurrency and malformed records need hardening.
  • src/dawchecker_security/classifiers/ — shell, file_access, package, MCP, DAW, base classifiers; heuristics, not sandboxing.
  • src/dawchecker_security/cli.py — command-line review/receipt interface; input validation improvements pending.
  • src/dawchecker_security/harness/wrapper.py — integration wrapper; caller must route all actions through enforcement.
  • config/default_policy.yaml — baseline risk rules.
  • tests/test_engine.py — core and classifier tests, including new policy precedence/context regression tests (not yet executed).
  • docs/INTEGRATION.md and examples/basic_review.py — integration guide and example.

Trust boundaries

  • Untrusted: prompts/model output, retrieved content, agent memory, agent-to-agent messages, tool/MCP inputs and outputs, package metadata, shell/path strings.
  • Must be host verified: agent identity, session/workspace binding, policy integrity, approval/key storage, enforcement gate.
  • Rule: model output must never grant permissions, change policy, or authorize itself.

StackAlign LLM hosting requirements

Not implemented in this repository: endpoint authentication/authorization, rate limits, token budgets, spending caps, concurrency ceilings, timeout/cancellation, GPU/CPU/RAM/storage limits, tenant isolation, context/secret redaction, privacy-safe audit logs.

Known gaps

  • Approval vault key permissions, symlink defense, atomic writes and schema validation.
  • Policy schema validation and fail-safe loading.
  • Recursive MCP argument inspection and tool-server validation.
  • Receipt locking/concurrency, malformed JSONL recovery, secret minimization.
  • CLI malformed input and boundary conditions.
  • Path canonicalization and symlink-aware resource checks.
  • Agent resource budgets, cancellation and containment.
  • Actual host enforcement and sandbox/process isolation.

Where features belong

  • Decision/context: core.py
  • Rules/config: policy/engine.py and config/default_policy.yaml
  • Approvals: approvals/memory.py
  • Receipts: receipts/store.py
  • New action type: classifiers/ plus tests
  • Agent/runtime integration: harness/wrapper.py and docs/INTEGRATION.md
  • CLI: cli.py plus tests

Governance

  • Branch-first; preserve main; no force push.
  • Minimal patches; maintain public behavior unless security requires change.
  • Tests must be run and reported honestly; no fabricated verification.
  • Update HTML and JSON together when architecture changes.
